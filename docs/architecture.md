# Архитектура

## Общая схема

```
Браузер ──► Next.js (App Router, Node runtime)
             ├── /(public)         серверные компоненты, данные из Prisma
             ├── /admin/*          серверный layout (сессия) + клиентские CRUD-страницы
             ├── /api/*            REST-эндпоинты: Zod-валидация → Prisma
             ├── middleware.ts     быстрый редирект на /admin/login без куки
             └── Prisma ──► PostgreSQL
```

## Слои

- **Публичная часть** — одна страница (`app/page.tsx`): серверные компоненты читают
  категории/блюда/настройки из БД; интерактив (sticky-навигация со scroll-spy,
  модальное окно блюда с галереей) — клиентские компоненты
  (`components/public/*`). Блюда передаются в клиентский компонент как plain-объекты.
- **Админка** — `app/admin/(dashboard)/*` защищены layout'ом с полной проверкой
  сессии на сервере; клиентские страницы работают с `/api` через fetch.
- **API** — каждый маршрут: `requireUser()` → `sameOrigin()` (CSRF) →
  `parseBody(zodSchema)` → Prisma → `audit()`. Сервер никогда не доверяет клиенту:
  все поля валидируются Zod-схемами из `lib/validation.ts`.
- **Роли**: `ADMIN` (пользователи, импорт) и `EDITOR` (контент). Проверка роли —
  в маршрутах `/api/users*` и `/api/import`.

## Безопасность

| Угроза | Защита |
|---|---|
| Подбор пароля | bcrypt cost 12; rate-limit: 5 неудачных попыток на email за 15 минут (`LoginAttempt`) |
| Кража сессии | httpOnly + SameSite=Strict + Secure (в prod) cookie; в БД хранится только SHA-256 хеш токена с AUTH_SECRET |
| CSRF | SameSite=Strict + проверка Origin на всех мутациях |
| XSS | React-экранирование; никаких dangerouslySetInnerHTML |
| IDOR/несанкционированный доступ | серверная проверка сессии в каждом API-маршруте и layout'е админки |
| Секреты | только в `.env` (вне Git); `.env.example` — шаблон |

## Хранение изображений

- Загрузки пользователей не хранятся в Git: `storage/uploads/` (вне репозитория),
  раздача через `/api/media/file/[...path]` с фиксированным Content-Type и кешем.
- Интерфейс `StorageDriver` (`lib/storage.ts`) позволяет переключиться на
  S3-совместимое хранилище (R2/MinIO) через `MEDIA_DRIVER=s3`.
- Ассеты исходного сайта — копия в `public/source-assets/` (владелец подтвердил права).

## Решения по стеку (и почему)

- **CSS портирован из исходной темы вместо Tailwind**: приоритет — пиксельное
  соответствие оригиналу (токены, Gilroy, сетка Bootstrap-подобная) и отсутствие
  зависимости от jQuery/Bootstrap.
- **Собственные сессии вместо Auth.js**: минимальная поверхность зависимостей,
  полный контроль над rate-limit и аудитом; схема проста и переносима.
- **Prisma**: типизированные миграции, seed, studio из коробки.

## Расширяемость

- Мультиязычность: добавить поля `titleEn/titleZh` (или таблицу переводов) и
  переключатель в `SiteHeader` — место сохранено.
- Заказы/оплата: модель `Product` уже имеет стабильные id; достаточно добавить
  `Order*`-модели и клиентскую корзину — публичный слой менять не нужно.
